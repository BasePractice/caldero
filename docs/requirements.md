# Реестр требований

Требования из [README](../README.md) разнесены по идентификаторам, каждое
снабжено критерием приёмки и фактическим статусом. Без этого проверить
реализованность требования невозможно: формулировка «пользователь создаёт
список желаний» не отвечает на вопрос, готово ли это.

**Приоритет** по MoSCoW: `M` — обязательно, `S` — следует, `C` — можно,
`W` — не в этот раз.

**Статус:** ✅ реализовано · 🟡 частично · ⬜ не начато

## Внешние ограничения

Не требования к системе, но то, что ограничивает её реализацию.

| № | Ограничение | Следствие |
|---|---|---|
| EXT-01 | Приём и вывод денежных средств требует статуса платёжного агента или договора с ним | FR-52 и FR-53 реализуются только против песочницы провайдера; решение — [ADR 0005](adr/0005-payment-flow.md) |
| EXT-02 | ЕСИА требует регистрации информационной системы и работы с УКЭП | FR-06 в учебном контуре нереализуем |
| EXT-03 | Публичные API маркетплейсов ориентированы на продавца, а не на покупателя | FR-24 и FR-50 могут оказаться невыполнимыми в заявленном виде; решение — [ADR 0004](adr/0004-marketplace-integration.md) |
| EXT-04 | KrakenD Community Edition не проксирует gRPC | кошелёк недоступен снаружи напрямую |

## Как поддерживать

Реестр — источник истины о том, что считается сделанным. При закрытии задачи
статус здесь обновляется; при появлении требования оно сначала попадает сюда
с критерием приёмки и только потом в работу.
