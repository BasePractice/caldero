# Правила работы над проектом

## Код

При написании и ревью любого кода руководствоваться [RULE.md](RULE.md) — это основной
документ по стилю, приоритетам и анти-паттернам. При конфликте `RULE.md` с уже
сложившимися соглашениями кодовой базы приоритет у кодовой базы (это прямо оговорено
в самом `RULE.md`), а расхождение оформляется отдельной задачей.

Принятые расхождения зафиксированы в [docs/adr/](docs/adr/): драйвер
PostgreSQL и структура каталогов — в [ADR 0003](docs/adr/0003-postgres-driver-and-layout.md),
библиотека OAuth2 — в [ADR 0002](docs/adr/0002-oauth2-library.md).

## Задачи

Все задачи живут в [TASKS.md](TASKS.md). Общий план работ, отсортированный
по критичности, — в [PLAN.md](PLAN.md).

### Статусы

У каждой задачи ровно один из статусов:

| Статус | Значение |
|---|---|
| `ЗАВЕДЕНА` | Задача сформулирована, к работе не приступали |
| `РАЗРАБОТКА` | Задача в работе прямо сейчас |
| `ОКОНЧЕНА` | Работа завершена, изменения проверены |

### Жизненный цикл

1. Задача заводится со статусом `ЗАВЕДЕНА`.
2. Перед началом работы статус меняется на `РАЗРАБОТКА`.
3. По завершении статус `ОКОНЧЕНА` — и сразу после этого **вся информация о задаче
   удаляется из `TASKS.md` бесследно**: и строка из списка, и детальный план.
   Задача никуда не переносится и не архивируется.
4. Делается коммит и push.

### Структура `TASKS.md`

- **Сверху** — динамический список задач. В нём **только** задачи в статусах
  `ЗАВЕДЕНА` и `РАЗРАБОТКА`.
- **Ниже** — детальный план реализации по каждой задаче из списка.
- Выполненных задач в файле не остаётся.

### Требования

Реестр требований — [docs/requirements.md](docs/requirements.md). При закрытии
задачи статус соответствующих требований обновляется. Новое требование
сначала попадает в реестр с критерием приёмки и только потом в работу.

### Заведение новых задач

Любой найденный по ходу работы баг, любая возникшая сложность и любая идея
по улучшению — **немедленно заводятся задачей** в `TASKS.md`. Не «держать в уме»,
не откладывать, не молчать.

## Коммиты

- В сообщении коммита указывается, что за задача была: её номер и название.
  Формат: `[T-000] Краткое описание сделанного`
- **Co-Author в коммитах не указывается.** Никаких `Co-Authored-By`.
- После завершения задачи — коммит и push.
